# 量化思路增量评估设计（2026-11-03）

## 背景

过去一个多月验证过的外部量化思路（Alpha101、Volrix、QuantJourney、斐波那契+FVG、订单流/VWAP、概率/鞅等）几乎全部"未通过"，之后就放弃了。用户提出：

> 有效、简单的因子早已被市场消化，单独评估几乎不可能显著为正。应该在当前本地方案的基础上迭代：只要新方案比当前方案更优，就融合进去，然后上线验证。

本文档把这个思路落成可执行的评估流程。

### 过去的门槛分两类

| 类别 | 例子 | 问的问题 | 是否误杀增量信息 |
|---|---|---|---|
| 单独成策略 | Alpha101、Volrix、QuantJourney、斐波那契+FVG | 这个因子/规则**单独**交易是否显著为正（G0 零假设校准 → G1 IC → G2/G3 扣费多空） | **会**。单独不赚钱的因子，仍可能改善现有决策 |
| 增量 | 订单流/VWAP、fq 止盈 | 相对提示词里已有的指标，**有没有新增信息** | 不会，方向正确 |

已有证据说明第一类门槛确实会漏掉东西：

- 因子 ensemble 的 rank IC 在样本外依然成立，但单独做多空组合是亏的，主要亏在空头侧的拉盘币。
- 这类因子"有信息、不能单独变现"，更适合用来修正现有决策。

### 但"比现在好就合并"不能直接用

1. **基线本身是亏的。** 实盘约 −0.077R/笔（2026-11-01 统计）。
   - 对亏钱的基线，"少交易"就能让总盈亏变好。
   - 增量评估必须区分两件事："每笔更好"和"只是做得更少"。
2. **多重检验。** 试的思路越多，偶然"更好"的就越多。必须记下尝试次数 K。
3. **大模型自身有随机性。** 同一提示词问两次，答案也会不同。离线比较要有噪声组。
4. **线上验证慢。**
   - 2026-11-03 的现有配对：factor-ensemble 运行 14 天，每边 80–86 笔，avgR 差 SE = 0.037。
   - SE 按 1/√n 缩小：30 天约 0.025，6 周约 0.021。
   - 要分辨 +0.05R 量级的改进，一组配对至少要跑 4–6 周。
   - 每条线最多同时跑 1–2 组配对，线上一年只能验证 10–20 个思路。
   - 所以离线必须做筛子：门槛可以放宽，但不能取消。

## 核心原则

1. **评估对象是"对基线的一处改动"，不是"一个独立策略"。** 每个思路都要写成对当前基线的具体改动，没法写成改动的思路不进入流程。
2. **主统计量是同一批数据上的成对差** Δ = 改动版 − 基线，不看改动版单独的收益。
3. **离线负责便宜地筛选，线上负责最终判定。**
   - 离线门槛放宽：不再要求单独显著为正；
   - 线上门槛预先登记：天数、笔数、判定规则写死，不看结果再改。
4. **"每笔更好"和"做得更少"分开记。** 只靠减少交易得到的改善，不算思路有效，而是另一个问题：基线该不该少交易。单独记录、单独决策。
5. **基线始终可回滚。** 合并后旧基线继续作为对照跑一段时间。

## 基线

每条交易线各有一个**当前基线**，用策略配置版本标识：

| 交易线 | 基线 | 版本标识 |
|---|---|---|
| 加密 LLM 交易员 | 当前正式交易员的策略配置（提示词、指标、闸门、风控） | `strategy_config_versions.config_hash`（已有，31 条历史） |
| 美股 LLM 交易员 | 同上 | 同上 |
| factor_quant 加密/美股 | 当前因子规则与持有周期 | `quant_targets.json` 的 rule + 策略配置版本 |

- 基线登记在 `data/evolution/baselines.json`，每条线一项：当前版本、生效时间、上一版本。
- 只有走完第 3 节的线上判定并经人工批准，才能更新基线。
- 用户默认说的"量化"指 LLM 交易路径（kernel 提示词/信号层），本文以它为主；factor_quant 用同一套框架，基线换成当前规则。

## 改动类型与离线评估方法

| 类型 | 例子 | 离线评估 | 现有工具 / 需新增 |
|---|---|---|---|
| A. 提示词输入字段 | 把因子值、订单流等作为参考字段喂给大模型 | 离线重放：基线组 vs 注入字段的变体组 | `cmd/llmreplay` 已有；**新增 `input_inject` 补丁**，按 record_id × symbol 注入预先计算好的字段值 |
| B. 开仓过滤/闸门 | 趋势过滤、追高否决、因子分位否决 | 在历史真实开仓上做反事实剔除，配**随机剔除安慰剂** | **新增** `scripts/backtest/incremental_filter.py`；放宽现有闸门时用 `gate_shadow_blocks`（8494 条，已有结果） |
| C. 出场/仓位规则 | 提前减仓、止损倍数、时间止损 | 在历史真实入场上，用 Backtrader 出场适配器分别跑基线规则和改动规则 | `scripts/backtest` exit 已有 |
| D. 提示词规则文字 | 复盘得出的教训、风格约束 | 离线重放 | `llmreplay` 的 `rules_text` / `system_append` 已有 |
| E. 候选币池/排序 | 按因子挑选给大模型看的币 | 离线只做可行性检查（覆盖率、换手），**直接进线上配对** | 改动的是整个输入，无法逐条配对重放 |

### A/D 类：离线重放

沿用 `LLM_EVOLUTION_LOOP_DESIGN_2026-11-02.md` 第 ③ 节的抽样、缓存、Backtrader 评分与噪声组，判定改成下面的分级（替代原来只用 `z_K` 的 pass/fail）。

**`input_inject` 补丁**

- 变体文件新增：
  ```json
  {"input_inject": {"file": "fields.jsonl", "anchor": "per_symbol", "label": "Factor reference"}}
  ```
- `fields.jsonl` 每行一条：`{record_id, symbol, text}`。
- 字段文字插入该 symbol 的行情块末尾。找不到锚点时，该样本标 `patch_miss`。
- 字段值必须只用决策时间之前的数据计算，生成脚本负责，评分前抽查。

### B 类：过滤器与随机剔除安慰剂

**输入**

- 评估期内基线的全部真实平仓交易，每笔有 R。
- 过滤条件在开仓时刻的取值。

**统计**

- 剔除率 p = 被剔除笔数 / 总笔数。
- 主统计：保留集 avgR − 全集 avgR。
- 安慰剂：同样剔除比例 p 随机剔除 2000 次，得到该统计量的零分布。
  - 随机剔除不改变期望 avgR，所以这一步检验的是"每笔更好"，不受"做得更少"影响。
- 同时报告：
  - 总 R 变化；
  - 被剔除集的 avgR 和 95% CI；
  - 按周聚类的 SE。

**闸门放宽**

- 用 `gate_shadow_blocks` 看被拦截信号的事后结果（`outcome` / `outcome_48h`）。
- 若被拦截集的 avgR 显著高于同期已执行集，说明闸门在误杀。
- 局限：影子结果按计划止损止盈先到先算，不是大模型逐周期管理的真实离场。

### C 类：出场规则

- 同一批历史真实入场，用 Backtrader 分别跑基线出场和改动出场。
- 逐笔配对差，按周聚类求 SE。
- 不改变入场，因此不存在"做得更少"的问题。但要报告持仓时长变化，因为占用保证金的时间会影响同时可开仓数。

## 离线分级判定（S1 筛选）

所有类型统一输出以下数值：

- 时间二分（前半 dev、后半 holdout）的 Δ 点估计；
- 合并后的 z；
- 噪声组的 |z|（A/D 类）或安慰剂分位（B 类）。

| 结论 | 条件 | 去向 |
|---|---|---|
| `invalid` | 噪声组 \|z\| ≥ 2；或有效配对点 < 100；或解析失败率 > 10%；或补丁命中率 < 80% | 修评估本身，不算一次尝试 |
| `strong` | 合并 z ≥ z_K（K 为该交易线账本里已评估的改动数，含本次）；且 dev、holdout 两半 Δ 都 > 0 | 优先排进线上 |
| `screen_pass` | 合并 z ≥ 1.0；且两半 Δ 都 > 0；B 类另需安慰剂分位 ≥ 90% | 排进线上队列 |
| `fewer_trades` | 改善主要来自交易数减少：B 类安慰剂分位 < 90% 但总 R 变好；或 A/D 类开仓率变化超过 ±50% | 不进线上；记入"基线交易频率"问题，单独决策 |
| `fail` | 其余 | 记账，放弃 |

### 为什么放宽到 z ≥ 1.0

- 在零假设下，单看 z ≥ 1.0 约有 16% 的概率误通过；加上"两半同号"后约 13%（蒙特卡洛 10⁶ 次）。
- 离线只是筛子，线上判定是独立的第二道关（见下一节）。两道都误过约 4%。
- 这比单独用 Bonferroni `z_K` 宽松得多，但仍可控。
- 线上名额有限，排队按合并 z 从高到低。

## 线上判定（S2 配对）

沿用 `scripts/promotion`：`create_pair` 建候选/对照模拟盘，`report` 出报告。新增"增量判定"模式。

**预先登记**（建对时写进 pair 元数据，之后不得修改）

- 主指标：avgR 差，按周聚类。辅助指标：每日配对 USDT 差、开仓数比、MaxDD。
- 最短运行：30 个配对日，且两边各 ≥ 50 笔平仓。
- 非劣效边际 m = 0.03R。

**判定**

| 结论 | 条件 |
|---|---|
| `harm_stop` | 运行 ≥ 14 天且 Δ < −2·SE：提前终止，记 fail |
| `promote` | 达到最短运行，Δ 点估计 > 0，单侧 95% 下界 > −m，且开仓数比在 0.67–1.5 之间 |
| `fewer_trades` | 达到最短运行，Δ > 0 但开仓数比 < 0.67：转入"交易频率"问题 |
| `extend` | 达到最短运行但不满足上面任何一条，且 SE > 0.02：延长 2 周，最多一次 |
| `reject` | 其余 |

**误判率估算**

- 零假设下，30 天 SE ≈ 0.025；"下界 > −0.03"等价于 Δ > 0.011，误通过概率约 33%。
- 再乘离线约 13% 的误通过率，两道都误过约 4%。

**和现有报告的关系**

- 现有 `report` 的 ready 要求日均 USDT 配对差的非劣效边际为 0.01 USDT/日，对增量改动过严。
- 增量模式以 avgR 为主指标，USDT 只作辅助，原有 ready 判定保留不变。

## 合并、保留对照与回滚（S3）

1. `promote` 之后由**人工批准**，才把改动写进正式交易员的策略配置。
   - 新配置的 `config_hash` 登记为新基线，`baselines.json` 记录上一版本。
2. **保留对照**：原对照模拟盘继续按旧基线运行 4 周。
   - 4 周内若新基线 Δ < −2·SE，提示回滚，回滚同样需要人工批准。
3. 下一个思路以新基线为对照，逐步往上迭代。
4. 实盘账户只在人工批准后变更。线上验证全部在模拟盘完成。

## 记账

`data/evolution/ledger.jsonl`（已有，只追加）每次评估追加一行，新增字段：

- `track`：crypto_llm / us_llm / fq_crypto / fq_us；
- `baseline_version`：基线的 config_hash；
- `change_type`：A–E；
- `stage`：S1 / S2 / S3；
- `verdict`；
- `K`：该交易线的累计尝试数；
- `delta`、`se`、`z`、`trade_ratio`、`placebo_pct`。

另外：

- 每次评估同时记进研究日志（`researchLog.ts` 和 `quant-research-log.html`），包括 `fail` 和 `fewer_trades`。
- `invalid` 不计入 K，但要记一行说明原因。

## 基线绝对表现单独监控

增量流程只回答"比现在好吗"，不回答"现在值不值得交易"。

- 实盘基线的 E[R] 按月计算一次，带 95% CI。
- 若连续两个月 CI 上界 < 0，单独提出"降低实盘规模或暂停"的决策，交给用户。增量流程不自动处理这件事。
- `fewer_trades` 类结论累积起来也归入这个问题。

## 过去被否决、值得用新流程重筛的思路

只重筛**因"单独不显著"被否决**、但有信息证据的思路；按"增量无效"否决的不重筛。

| 思路 | 过去结论 | 改写成的改动 | 类型 |
|---|---|---|---|
| 因子 ensemble | rank IC 样本外成立，多空亏 | 已在线上配对（factor-ensemble，14 天，样本不足）；继续跑，用新判定 | A |
| Alpha101 加密 | 有 IC，换手吃掉收益 | 取 IC 最稳的几个因子做参考字段；或按因子分位否决开仓 | A / B |
| 追高/逆势类失败模式 | 自动复盘 `failure_mode` 统计（待积累） | 对应否决条件 | B |
| 提前减仓 0.8R | 已在线上配对（10 天，样本不足） | 继续跑，用新判定 | C |

不重筛：

- 订单流/VWAP：已经是增量测试，结论是无增量。
- Wyckoff/VP：G0 未通过即停止，无新证据不再提。
- 斐波那契+FVG：扣费前就亏，过滤器无效。

## 不做的事

- 不因离线 `screen_pass` 直接上线，必须走线上配对。
- 不自动修改正式交易员配置，合并与回滚都需要人工批准。
- 不把"做得更少"算作思路有效。
- 不在看到线上结果后修改预登记的指标、边际或运行时长。
- 不用 5 天、两周这类短窗口的结果决定合并。
