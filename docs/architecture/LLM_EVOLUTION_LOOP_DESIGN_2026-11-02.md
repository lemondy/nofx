# AI 交易员进化闭环设计（2026-11-02）

## 背景与目标

用户希望 AI（大模型）交易员能从历史交易里逐步迭代、"进化"。参考对象为 [chrisworsey55/atlas-gic](https://github.com/chrisworsey55/atlas-gic)。

### ATLAS 的做法

1. 把 25 个角色的提示词当作"权重"。
2. 每 5 个交易日改写夏普最低角色的提示词，一次只改一处。
3. 5 天后看夏普是否改善：改善就 git 保留，否则回滚。
4. 另按日给每个角色调整影响力权重，范围 0.3–2.5。

### 为什么不照搬

依据是它仓库自带的 `results/`：

- **全期是亏的。** 2024-09 → 2026-03 全期收益 −5.91%（`summary.json`），README 里的 +22% 只是部署阶段的一段。
- **保留决定基本是噪声。**
  - 5 天夏普的标准误远大于单次提示词改动的效应。
  - 54 次修改里保留了 16 次，其中一次是夏普 −0.45 → −0.44，也被保留。
  - 有一个提示词膨胀了 143 倍，是典型的噪声驱动过拟合。
- **核心代码没有公开。** 自动研究与打分模块、训练出的提示词都缺失。

### 只借三点

1. 每次只改一处。
2. 每次改动都有审计轨迹。
3. 先验证再保留，失败就回滚。

### 统计功效（真实数据）

两组现有候选/对照模拟盘跑约 2 周后，每边 40–80 笔：

- avgR 差的 SE 约 0.03。
- 要看出 +0.05R 量级的改进，一次线上实验需要 3–4 周。

所以只靠线上 A/B，一年只能迭代十来次。**必须先离线筛选。**

## 闭环总览

```
① 自动复盘 ──→ ② 单点提案 ──→ ③ 离线重放评估 ──→ ④ 模拟盘候选/对照 ──→ ⑤ 人工上线/回滚
 (归因数据)      (一次一处)       (主要筛子)          (现有 promotion)      (版本号)
     ↑                                                                        │
     └──────────────────────────── 新交易 ─────────────────────────────────────┘
```

本期实现 ① 和 ③。② ④ ⑤ 先以人工方式衔接，下一期再自动化：

- ② 由人或大模型手写变体文件。
- ④ 用现有 `create_pair`。
- ⑤ 手动改策略配置。

各环节只做一件事：

- ① 的结论只用来**产生假设**。复盘时大模型已经知道结果，有后见之明偏差，不能当证据。
- 证据只来自 ③ 和 ④。

## ① 自动复盘（本期）

### 运行方式

- 后端进程内的后台任务，每小时一次，避免跨进程写 SQLite 引起 `SQLITE_BUSY`。
- 按用户开关启用：在 `review_prompt_configs` 上新增 `auto_review_enabled`，默认关，复盘设置里加开关。
- 处理范围：
  - 该用户名下 `ai_managed=1`、`review_status='pending'` 的已平仓日志；
  - 只看最近 90 天，旧的到下一期再说；
  - 平仓时间早于当前 10 分钟以上。
- 每次最多 50 笔，按平仓时间从早到晚。每次大模型调用包含 ≤10 笔，积压会在若干小时内消化。
- 使用该用户的默认 AI 模型，与 `callReviewAI` 一致。

### 每笔交易的输入

- **日志事实**：方向、入场/出场价、杠杆、持仓时长、平仓原因、扣费净盈亏、R 倍数（有计划止损时）。
- **开仓时的决策**：
  - 同 symbol 与方向、入场前 30 分钟内最近一条成功开仓 `decision_records`（与 `matchOpenDecision` 同口径）；
  - 截取该 symbol 的推理（`reasoning`）和 CoT 片段，≤2000 字。
- **持仓期价格路径（可选）**：
  - 若后端已有可复用的 K 线读取函数，计算 MFE/MAE（以 R 计）；
  - 拿不到就省略，并在提示中说明缺失。

### 输出

大模型输出严格 JSON，逐笔写回。

**新增列 `failure_mode`**：固定词表，便于聚类；无法判断时填 `other`。

| failure_mode | 含义 |
|---|---|
| `chased_entry` | 追涨/追空入场 |
| `counter_trend` | 逆大级别趋势 |
| `weak_setup` | 信号不足、勉强入场 |
| `stop_too_tight` | 止损过近被扫后行情按原方向走 |
| `stop_too_wide` | 止损过远，单笔亏损过大 |
| `early_exit` | 过早离场，错过计划目标 |
| `late_exit` | 浮盈回吐、离场过晚 |
| `size_too_large` | 仓位或杠杆过大 |
| `market_shock` | 突发行情，无法事前识别 |
| `no_mistake` | 过程正确、结果不好（或盈利交易无明显错误） |
| `other` | 其他 |

**已有列**：

- `mistake_category`：strategy | execution | risk_control | market | none。
- `strategy_tag`：已有词表。
- `executed_as_plan`。
- `lesson`：一句可执行的教训，≤120 字；`no_mistake` 时可留空。
- `deviation_note`。

**状态字段**：

- `review_status='ai_reviewed'`：新值，与人工 `reviewed` 区分。人工在页面再次保存时改为 `reviewed`，人工结论优先。
- AI 自动复盘**永远不覆盖** `reviewed` 的行；写入时用条件更新保证这一点。

### 下游

- `handleAIExtractRules` 改为同时读取 `reviewed` 和 `ai_reviewed`。
- 日志统计接口增加按 `failure_mode` 的分组：笔数、扣费净盈亏、avgR，供提案参考。
- 前端改动：
  - 复盘页显示 `failure_mode`；
  - 筛选里加「AI 已复盘」；
  - 统计区加失败模式分组表；
  - 复盘设置加自动复盘开关。

### 失败处理

- 大模型调用或 JSON 解析失败：本批跳过，下一小时重试；同一笔累计失败 3 次后标 `review_status='ai_failed'`，不再重试。
- 调用前检查用户是否启用了开关。

## ③ 离线重放评估（本期）

### 思路

1. 从历史 `decision_records` 抽样，用同一模型分别按原提示词（基线）和改动后的提示词（变体）重新提问。
2. 对两边产生的开仓决策，用 Backtrader 按同一套出场规则模拟，比较每个决策点的 R。
3. 再用原提示词多问一遍，作为噪声组，测出大模型自身的随机性。

### 组件一：Go 命令 `cmd/llmreplay`

**数据库与安全**

- 只读打开数据库（`mode=ro`），不写库，不接触交易所或下单。

**主要参数**

- `--trader`：id 或名称。
- `--since` / `--until`：UTC。
- `--sample N`：默认 600。
- `--seed`。
- `--variant variant.json`。
- `--arm baseline|variant|noise`。
- `--noise-subset M`：默认 200，噪声组只跑前 M 个样本。
- `--concurrency`：默认 3。
- `--model`：默认用该交易员配置的 AI 模型；可指定 `ai_models` 的 id。
- `--out`：默认 `data/evolution/replay/`。

**抽样**

- 只取 `success=1` 且两段提示都非空的记录。
- 按"原决策是否含开仓"分两层抽样：开仓层与其余层各占一半。
- 记录各层权重（层大小 / 抽样数），供评分做加权。
- 同一 `--seed` 必须得到同一样本。
- 样本清单写到 `sample.json`，所有组共用。

**变体文件 `variant.json`**

```json
{
  "id": "no-chase-v1",
  "hypothesis": "chased_entry 是最大失败模式；要求回踩确认可减少追高亏损",
  "source": "auto-review failure_mode 统计 2026-11-0x",
  "system_append": "…追加到系统提示末尾的文字…",
  "system_replace": [{"old": "原文片段", "new": "替换文字"}],
  "rules_text": "## Review Rules\n- …"
}
```

- `rules_text` 插入用户提示里规则段的位置：`## Current Positions` 或 `Current Positions: None` 之前。
- 每个 `system_replace.old` 必须在样本的每条系统提示里都恰好出现一次，否则该样本标 `patch_miss`。全部样本都失败则拒绝运行。
- 变体内容取哈希，作为缓存键的一部分。

**调用与缓存**

- 调用使用现有 `mcp` 客户端。
- 结果按 `(record_id, arm, variant_hash, model, repeat)` 追加写入 JSONL 缓存，中断后可续跑；基线组可被多个变体复用。

**解析**

- 用内核现有解析逻辑，`kernel` 导出一个只读包装 `ParseReplayDecisions(resp string)`：
  - 复用 `parseDecisionsPerItem` 与 `resolveBatchConflicts`；
  - 账户和闸门参数用记录里能拿到的值，拿不到就填中性值。
- 线上解析之后还有防追高闸门、规则检查、风控等过滤，重放**不做**这些。基线和变体口径一致，所以比较仍然公平，但与实盘决策不完全可比。

**每条输出包含**

- 记录 id、时间、arm、开仓决策列表：symbol、方向、市价/限价、入场价、止损、止盈、置信度。
- 原始回复的哈希、耗时、错误。

### 组件二：Python 评分 `python -m scripts.backtest replay-score`

1. 把每组的开仓决策转成现有 `signals` 格式，用决策时间作为信号时间，不做真实成交匹配，所有组同口径。
2. 用现有 Backtrader 入场与出场适配器模拟：
   - 止损、止盈取决策给出的值，没有止损的不计入并计数；
   - 时间止损默认 72h；
   - 限价单有效期沿用 `entry` 默认值。
3. 每个决策点的结果 = 该点所有开仓的 R 之和，不开仓记 0。
4. 主统计：
   - 配对差：每点 `d = R_variant − R_baseline`；
   - 按抽样权重加权，按 UTC 日聚类求 SE 和 95% CI。
5. 噪声组同法算 `R_noise − R_baseline`，作为健康检查。
6. 辅助指标：
   - 开仓率变化；
   - 决策一致率：基线 vs 噪声、基线 vs 变体；
   - 方向翻转数；
   - 每笔开仓 avgR；
   - 按 `failure_mode` 关联的变化（若能匹配到日志）。

### 判定与记账

账本 `data/evolution/ledger.jsonl` 只追加，每个被评分的变体记一行：

- 变体 id、哈希、假设、样本参数、模型、各统计量、K；
- K 为截至当前账本里已评分变体的累计数，含本次。

判定：

| 结论 | 条件 |
|---|---|
| `invalid` | 噪声组 \|z\| ≥ 2，或有效配对点 < 100，或解析失败率 > 10% |
| `pass` | 变体 z ≥ `z_K`，其中 `z_K = Φ⁻¹(1 − 0.05/(2K))`；且开仓率变化不超过 ±50%，防止"什么都不做"式变体靠少开仓蒙混 |
| `fail` | 其余 |

- `invalid` 说明重放本身不稳，结论无效。
- 开仓率限制可配，超出时写 warning，需要人工复核。
- `pass` 的变体进入 ④ 线上候选/对照，**不自动上线**。

### 成本

- 实测每次决策调用约 3.5 万字符（约 1 万 tokens），模型响应约 100 秒。
- 600 个样本、并发 3，单组约 6 小时。
- 一个新变体只需跑变体组；基线和噪声组每个"交易员 + 时间窗 + 模型"组合只跑一次。

### 局限

1. 输入里的持仓状态来自真实历史，不是反事实持仓。因此重放评估的是"给定当时状态的逐周期开仓决策"，不评估持仓管理与离场。
2. 用今天的模型回答过去的提示：基线与变体同模型，比较公平，但不等于当时实盘。
3. 出场规则固定为决策给出的止损止盈加时间止损；实盘里大模型逐周期管理离场，两者不同。
4. 样本来自单一市场阶段，结论有阶段偏差。线上 ④ 用来补这一块。

## ② ④ ⑤（下一期）

- **②**：每周最多一个提案，由大模型基于 `failure_mode` 统计生成。
  - 提案必须是 `variant.json`、硬规则或策略参数之一，不允许整段改写提示词。
  - `system_append` 有长度上限，防止提示词膨胀。
- **④**：`pass` 的变体自动生成 `create_pair` 的预演命令，由人确认后建对；判定沿用现有 `report`。
- **⑤**：变体上线需要人工批准；策略配置写入变体 id 作为版本号，回滚即恢复上一版本。

## 不做的事

- 不按 5 天表现保留或回滚。
- 不让提示词无上限增长。
- 不自动生成新角色。
- 不做按影响力权重分配的多角色体系。
- 不做模拟未来训练。
- 不自动修改任何线上交易员配置。
