# Kronos 路径不利概率作 LLM 开仓否决（S1 预注册，2026-11-11）

来源评估：`docs/research/2026-11-10-kronos-kit-assessment.md` 的 H1。

- 本检验是增量评估框架的 S1，B 类（开仓过滤），track 为 `crypto_llm`，**K=5**（之前 4 个 S1），strong 门槛 z_K = 2.576，screen_pass 门槛 z ≥ 1。
- 本文在写任何研究脚本、下载任何真实 K 线、计算任何真实交易上的预测之前提交。提交后不修改；运行只做一次；失败不调参，不换模型、阈值或周期重跑。
- **本文提交时尚未获得运行许可。** 运行需要用户明确同意。

## 0. 问题

LLM 加密交易员的实盘期望 R 为负，入场没有优势。Kronos 是在 45 个交易所、120 亿根 K 线上预训练的 K 线基础模型（arXiv 2508.02739，预训练数据截止 2024-06）。它能否在开仓时识别出“多数可能路径都朝不利方向走”的交易，并通过否决这些交易提高保留交易的平均 R？

## 1. 样本（冻结，只读）

- **交易：** `data/llm_trim_offline/export_v1/trades.jsonl`，sha256 `8abfa110e9ae7e84981150572ea1954178f263f9ba1a0690163d305157382121`。
  - 共 439 笔，115 个币，入场时间 2026-09-29 至 2026-11-08，5 个加密 LLM 交易员（实盘 1 个，只含 `ai_managed=1`；模拟 4 个）；
  - 做空 309 笔，做多 130 笔。
- **每笔 R：** 取 `data/llm_trim_offline/s1_v1/results.json` 中 `trades[i].no_trim.r`（sha256 `ddce670b658a5abbe40dc04dd51927a0244c55a7ddab8ac75e3e87fd8b14d0b5`）。
  - 该值由 Backtrader 撮合计算：入场价到实际出场价，taker 双边各 5bp，不含减仓；
  - 439 笔全部为有限值，交易 ID 与导出文件一一对应。
  - 敏感性（只作描述）：用同一文件中的 `baseline.r`（1.2R 减仓档）重算一次。
- **已知污染（如实披露）：**
  - 这批交易已用于提前减仓（PR #107）、DVOL 仓位缩放（PR #111）、相关性状态缩放（PR #113）三项研究，都是出场或仓位研究；
  - 因子否决做多研究（2026-11-04）用过与之重叠的做多交易；
  - 此前没有任何研究按 K 线模型的预测给这批交易分组；
  - 写本文前只看过笔数、多空数、R 是否有限，没有看过任何按预测分组的 R。
- **Kronos 的样本外性：** 预训练截止 2024-06，权重最后修改 2025-09-09，交易全部在 2026-09 之后。

## 2. 价格数据

- 每笔交易下载币安 U 本位永续 5m K 线：
  - 取入场时间 t_e 之前已收盘的最后 512 根，即收盘时间 ≤ t_e 的 512 根；
  - 用 `scripts/backtest/market_cache.fetch_binance_klines`，请求间隔 ≥ 0.3 秒；
  - 字段 [openTime, open, high, low, close, volume, quoteVolume]，amount 取 quoteVolume。
- 存放于 `data/kronos_veto/kl5m_pre/{SYMBOL}_{entry_ms}.json`，manifest 记录每个文件的 sha256。下载后保留，不删除，不进 git。
- **数据校验：**
  - 一笔交易的可用 K 线 < 480 根，或 512 根内有缺口（相邻 openTime 差 ≠ 5 分钟），视为“无预测”；
  - 无预测的交易保留（drop=false），单独报告笔数；
  - 无预测占比 > 5% 判整个研究 invalid。

## 3. 模型与读数（全部固定）

- **模型：**
  - `NeoQuasar/Kronos-small` 版本 `901c26c1332695a2a8f243eb2f37243a37bea320`；
  - `NeoQuasar/Kronos-Tokenizer-base` 版本 `0e0117387f39004a9016484a186a908917e22426`；
  - 代码 `shiyu-coder/Kronos` 提交 `67b630e`；
  - safetensors 格式，零样本，不微调。
- **输入：**
  - 512 根 OHLCV + amount；
  - 时间戳取各根 K 线的 openTime（UTC），预测时间戳为之后连续 60 根；
  - 按 `KronosPredictor.predict` 的方式处理：窗口 z-score，裁剪 ±5。
- **采样参数：** max_context=512，T=1.0，top_p=0.9，top_k=0，16 条路径，pred_len=60（5 小时，接近持仓中位 5.4 小时）。
  - 保留每条路径，不取均值；
  - 随机种子 `20261111 + trade_id`，每笔调用前设 `torch.manual_seed`；
  - 设备用 CPU：冒烟测试中同种子重跑的差值为 0，每次预测约 30 秒，439 笔约 3.7 小时；MPS 也可复现，但与 CPU 结果不同，所以固定用 CPU。
- **读数：**
  - 参考价 P0 = 上下文最后一根 5m 的收盘价；
  - 第 k 条路径第 60 根的收盘价为 C_k；
  - 做多时 C_k < P0 记为不利，做空时 C_k > P0 记为不利；
  - p_adverse = 不利路径数 / 16。
- **否决规则：** p_adverse ≥ 0.75（即 16 条中至少 12 条不利）则 drop=true；否则 drop=false。
  - 每笔样本交易都写一行掩码 `{trade_id, drop}`。
- **写本文前的合成数据诊断（不涉及真实价格，见评估文档第 6 节）：**
  - 在 50 条无漂移 GBM 上，路径方向几乎一致：82% 的序列 p_up ≤ 0.125 或 ≥ 0.875；
  - 预测的 5 小时均值偏移中位数为 2.5 个 σ√60，路径离散度只有 0.6 个 σ√60；
  - 偏移与最后收盘价在窗口中的 z 分数相关 −0.78。

  所以 p_adverse 实际上近似于一个确定性的“向窗口均值回归”方向判断。按合成数据估计，剔除率约 40%。阈值仍按原设计取 0.75，不根据这次诊断调整。
- **零成本代理（同时计算，见第 4 节）：**
  - z_last = (P0 − 窗口 512 根收盘价均值) / 窗口收盘价标准差；
  - 代理否决：对每笔交易计算 side·z_last（做多取 +z_last，做空取 −z_last）。在全部 439 笔中，按 side·z_last 从大到小剔除，笔数与 Kronos 规则的剔除笔数相同；并列时按 trade_id 升序。
  - 含义：做多时价格已在窗口高位、做空时已在低位，就否决。

## 4. 判定（直接调用现有框架）

- 用 `scripts.backtest.incremental_filter.filter_statistics`（seed 20261103，安慰剂 2000 次）和 `decide_verdict`。
  - 前后两半按入场时间切分；
  - verdict 按框架的先后顺序判定：invalid → fewer_trades（剔除率 > 0.5）→ strong / screen_pass → fewer_trades → fail。
- **本研究额外的 invalid 条件：**
  - 剔除笔数 < 20（没有统计力）；
  - 无预测占比 > 5%；
  - S0 任一项不过。
- 结果写入账本 `data/evolution/ledger.jsonl`：track `crypto_llm`，idea_id `kronos-entry-veto-v1`，baseline_version `no-entry-veto`。
- **结论只决定是否进入 S2。** 进入线上配对队列需同时满足以下两条，不直接上线：
  1. Kronos 规则的 verdict 为 screen_pass 或 strong；
  2. Kronos 的 ΔavgR 大于代理否决的 ΔavgR（同剔除笔数，同一套 R）。

  不满足第 2 条时记为“信息可由代理复现”，Kronos 不接入。代理本身若表现好，只能另写预注册检验，不在本次结论里直接采用。
- 代理否决只作为对照计算一次，不写账本，不计 K。

## 5. S0 闸门（在计算任何 Δ 之前完成，不过则 invalid）

1. **复现性：** 随机抽 10 笔（种子 7），重跑一遍，p_adverse 必须完全一致。
2. **数据：** 第 2 节的覆盖率要求。
3. **合成数据检查：** 对 50 条无漂移 GBM 序列，p_up 的均值必须落在 [0.35, 0.65]。不满足说明模型或读数有系统偏向，判 invalid。
   - 写本文前已用草稿脚本跑过一次：MPS，种子 11+s，均值为 0.531；
   - 正式运行时用研究脚本在 CPU 上重跑。

## 6. 只作描述（不影响 verdict，不计 K）

- 阈值 0.6875 和 0.8125 下的 ΔavgR；
- 多空分开的 ΔavgR；
- 用 `baseline.r` 重算的 ΔavgR；
- 方向命中率：sign(路径终点均值 − P0) 与入场后 5 小时实际收益符号的一致率；
- side·(路径均值收益) 与 R 的 Spearman 相关；
- side·(过去 5 小时收益) 与 p_adverse 的相关，用于判断模型是否只是在重述近期动量或反转；
- 每笔推理耗时。

## 7. 局限

- 439 笔交易，剔除 30% 时，安慰剂标准误约 0.03–0.04R，只能检出较大的效应。
- R 用“整仓入场到实际出场”计算，没有包含减仓，与实盘的实际 R 有小差异；两组共用同一口径。
- LLM 是按周期管理出场的，否决后的反事实是“不开仓”，没有考虑 LLM 可能改开其他币。
- 只检验一个模型（Kronos-small）、一个周期（5m）和一个阈值。KiT 不在本检验内：它的权重需要不安全的 pickle 加载，而且训练集只有 28 个加密币。
