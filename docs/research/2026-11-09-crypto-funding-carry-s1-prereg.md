# 资金费 carry（现货多 + 永续空）离线 S1 预注册（2026-11-09）

## 0. 背景与问题

来源是 `docs/research/2026-11-09-quantbot-math-assessment.md` 的 H1（网页卡片 2.6）。

- **机制：** 永续合约资金费为正时空头收费。持有同等币数量的"现货多 + 永续空"，价格风险基本对冲，收益约等于收到的资金费，减去成本和两腿价差（基差）的变化。
- **在 nofx 中的位置：** nofx 从未把资金费本身当作收益来源，只用作成本或因子输入。
- **要回答的问题：** 按资金费门槛开关的 carry 策略，扣除真实成本和资金占用后，是否有值得做模拟验证的独立收益。

**性质：** 独立的市场中性策略，不是对现有基线的增量。

- 新登记 track `crypto_carry`，本检验 K=1。change_type 记为 E（新能力）。
- 需要在 `scripts/backtest/evolution_ledger.TRACKS` 中加入 `crypto_carry`。
- 本研究只做离线回测，不改交易配置，不启动交易员，不下单。

## 1. 标的与区间

- **主检验：** BTCUSDT 和 ETHUSDT 两个 sleeve，各占一半资本，互不再平衡。
- **描述项（不参与判定）：** SOLUSDT、BNBUSDT、XRPUSDT、DOGEUSDT，各自单独报告。
- **区间：** 交易日 2020-01-01 至 2026-11-06（UTC，含两端）。2019-12-25 起的数据只用于计算信号。
- **两半：** 按交易日数平分成前后两半，奇数日数时前半取 ⌊n/2⌋。
- **近一年：** 2025-11-07 至 2026-11-06。

## 2. 数据（下载后保留，不删除）

| 数据 | 来源 | 存放位置 |
|---|---|---|
| 资金费逐次结算 | Binance `/fapi/v1/fundingRate` 全历史 | `data/carry/funding/{SYMBOL}.json`，行为 [fundingTime_ms, rate, markPrice] |
| 现货日线 | Binance `/api/v3/klines`，interval 1d | `data/carry/spot_1d/{SYMBOL}.json` |
| 永续日线 | Binance `/fapi/v1/klines`，interval 1d | `data/carry/perp_1d/{SYMBOL}.json` |

- 永续日线重新下载，与现货同一口径，不用因子面板。
- 另写 `data/carry/manifest.json`，记录每个文件的 sha256、行数和区间。
- **校验（任一不过，判 invalid）：**
  - 主检验区间内，现货与永续日线缺失的天数各 ≤ 0.5%；
  - 资金费结算间隔与该币当时的结算周期（8h 或 4h）一致，缺失的结算次数 ≤ 0.5%；
  - 永续日线收盘价与因子面板 `data/factor_mining/crypto/daily` 的收盘价逐日吻合，偏差 ≤ 0.1% 的比例 ≥ 99%。

## 3. 规则（参数固定，不做网格）

**信号：** 在 UTC 日 d 收盘时计算过去 7 天的年化资金费率：

> APR_d = Σ(fundingTime ∈ [open_{d−6}, close_d) 的费率) / 7 × 365

只用 fundingTime 严格早于决策时刻（open_{d+1}）的结算，不含 open_{d+1} 那一次。

**开关（带滞回）：**
- 空仓且 APR_d ≥ 10%：在 d+1 开盘开仓；
- 持仓且 APR_d < 2%：在 d+1 开盘平仓；
- 其他情况维持原状态。

**仓位与资本：**
- 每个 sleeve 的资本 C 分成两部分：现货名义 N = 0.75C，永续保证金 0.25C（相当于永续 3 倍杠杆）。
- 开仓时买入 Q = N / 现货开盘价 数量的现货，同时做空 Q 数量的永续。
- 持仓期间按币数量对冲，不做日内或每日再平衡。
- 每次开仓都用该 sleeve 当时的全部权益重新计算 N 和 Q。
- 空仓时资本闲置，收益记为 0，不计 USDT 理财收益。

**资金费：** 持仓期间（t_entry < fundingTime ≤ t_exit）的每次结算，空头收到 rate × Q × markPrice。rate 为负时付出。markPrice 缺失时用永续当日收盘价，并计数披露。

**保证金追缴：**
- 持仓期间，某日永续最高价 ≥ 开仓价 × (1 + 0.25/0.75 − 0.005) 时，记一次"保证金击穿"，即永续亏损吃掉保证金（维持保证金率按 0.5%）。
- 击穿时两腿在当日以该价格强制平仓，并照常扣成本；次日起按信号重新判断。
- 实际交易中可以用现货腿的浮盈补充保证金，所以这里的处理偏保守。

**成本（每腿每次成交）：**
- 现货 taker 费 0.10% + 滑点 0.03%；
- 永续 taker 费 0.05% + 滑点 0.03%；
- 一次完整开平仓共四次成交，合计约 0.42% 名义。

**撮合：** 必须走 Backtrader（`scripts/backtest`），现货、永续两个数据源。
- 资金费用 broker 现金流计入；
- 另写纯算术的参考实现，逐日权益差 ≤ 1e-9 才算实现正确。

## 4. 指标

主序列是 BTC、ETH 两个 sleeve 合计的**资本日收益**（扣除全部成本和资金费后的权益变化 / 前一日权益）。

- 年化收益 = 日均收益 × 365；年化波动 = 日标准差 × √365；夏普用 √365。
- z = 日均收益 / SE。SE 按 UTC 周（周一开始）聚类，用 `incremental_filter.weekly_statistics`，与研究框架一致。
- MaxDD 按日末权益计算。
- 同时报告：
  - 持仓天数占比、开平仓次数、保证金击穿次数；
  - 资金费收入、成本、基差盈亏三部分的拆分。

## 5. 判定（track crypto_carry，K=1，z_K = 1.96）

| 判定 | 条件 |
|---|---|
| invalid | 第 2 节数据校验不过，或 Backtrader 与算术参考不一致 |
| pass（值得模拟验证） | 全部满足：年化收益 ≥ 5%；z ≥ 1.96；前后两半年化收益都 > 0；近一年年化收益 > 0；MaxDD ≤ 10% |
| weak（有信号但不足以上线） | 不满足 pass，但年化收益 > 0 且前后两半都 > 0 |
| fail | 其他情况 |

- 5% 的门槛对应：持有稳定币也能拿到的低风险收益量级，加上交易所对手风险和运维成本。低于这个水平，不值得增加一条交易线。
- **后果：**
  - pass：建议设计模拟盘接入方案。需要给加密模拟盘补现货腿，另行提出，并需用户同意。
  - weak 或 fail：不接入，记录在案。

## 6. 仅描述，不参与判定

- 始终持有的 carry（不看门槛）：同成本口径。
- 零成本版本：看成本吃掉多少。
- 按年份的收益。
- 四个描述币种各自的结果。
- 资金费转负期间的最大亏损。
- 门槛的敏感性：开仓 5%、15%，平仓 0%、5% 的组合，只报告，不改判定。

## 7. 已知偏差与局限（预先承认）

- **偏差：**
  - 资金费曾以"每日均值"的形式作为因子输入，用过这份数据（`f_0ce8b2ee` 含 EMA(funding)），但从未计算过 carry 收益；
  - BTC 与 ETH 的资金费水平大致属于公开常识，选择这两个标的不完全是盲选；
  - 只用日线，不模拟日内基差波动和日内强平。
- **前视：** 信号只用决策时刻之前的结算，成交在下一日开盘。
- **幸存者偏差：** 只选当前仍上市、流动性最好的币，偏乐观；描述币种也是幸存者。
- **多重检验：** 主检验只有一组参数。敏感性表只用于描述，不得事后改用其中更好的组合。
- **没有模拟的风险：**
  - 交易所对手风险；
  - 现货与合约账户之间的资金划转延迟；
  - 极端行情下的 ADL（自动减仓）。
