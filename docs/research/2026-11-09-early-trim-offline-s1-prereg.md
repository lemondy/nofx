# 提前减仓 0.8R 离线复核（S1 预注册，2026-11-09）

## 0. 背景与问题

线上配对 `early-trim-0p8r` 比较两种减仓档：候选在浮盈 0.8R 时市价减仓 1/3，对照在 1.2R 时减仓 1/3。其余风控完全相同，配置差异只有 `risk_control.tp_trim_at_r` 一项。

截至 2026-11-09 配对已运行 16 天，avgR 差为 −0.033R（SE 0.060）。按现有数据推演，即使真实差值为 0，到 44 天通过的概率也只有约 3%。

减仓是出场规则，不改变入场，所以可以拿已有的真实交易离线比较两个减仓档，样本是配对的 3 倍多。本检验是 S1，类型 C（出场规则），track 为 `crypto_llm`，K=2（之前 1 个 S1）。

## 1. 样本（只读数据库）

所有满足以下条件的 `trader_positions` 记录：

- `status='CLOSED'`，`initial_stop_loss > 0`，`exit_time` 与 `exit_price` 有效；
- 入场时间满足 2026-09-29T00:00:00Z ≤ `entry_time` < 2026-11-09T00:00:00Z。起点是 R 单位减仓档上线的日期；
- 交易员是以下之一：
  - 实盘加密 `d7ff3764_…_deepseek_1787982996`，且 `ai_managed=1`，以排除用户手动单；
  - 模拟盘 `a2dc5705_…`、`a8eb1bdf_…`（ensemble 配对两臂）；
  - 模拟盘 `ec830bb2_…`、`895dc8b3_…`（减仓配对两臂）。

预查数量：454 笔，117 个币，平均持仓 6.8 小时，最长 71.5 小时。只查了数量，没有看任何收益。

导出的交易冻结为 JSONL 文件，sha256 记入结果。

## 2. 价格数据

- 每笔交易下载 Binance U 本位 1m K 线，区间为 [入场分钟 − 5 分钟, 出场分钟 + 5 分钟]，使用 `scripts/backtest/market_cache.fetch_binance_klines`，请求之间至少间隔 0.3 秒。
- 存放于 `data/llm_trim_offline/kl1m/{SYMBOL}_{entry_minute_ms}.json`，另有 manifest 记录每个文件的 sha256。数据下载后保留，不删除。
- **校验（任何一项不过，整个研究判 invalid）：**
  - 每笔交易在 [入场分钟, 出场分钟] 内缺失的分钟数 ≤ 1%；不满足的交易剔除，剔除总数 ≤ 5%；
  - 入场价落在入场分钟 K 线 [low×0.998, high×1.002] 内的比例 ≥ 95%。

## 3. 反事实模型（两臂都模拟，只比较减仓那 1/3）

记号：方向 s（多 +1、空 −1），入场价 E，初始止损 SL0，R = |E − SL0|，pnlR(p) = s·(p − E)/R。实际最终出场价为 X，出场时间为 Tx。

对减仓档 L（候选 0.8，对照 1.2）：

1. **触发：** 从入场分钟的下一根 1m K 线开始，到收盘时间 ≤ Tx 的最后一根为止，取第一根收盘价 c 满足 pnlR(c) ≥ L 的 K 线。这对应线上风控循环每分钟按标记价检查一次。
2. **成交：** 减仓 1/3，市价成交，价格为 c 加 3bp 不利滑点，taker 费 5bp。
3. **残余仓位：** 两臂都在实际出场价 X 平掉，taker 费 5bp。
   - 依据：盈亏平衡保护在 0.75R 先于两个减仓档生效（`breakeven_arm_r=0.75`），减仓本身不改动保护单，所以残余仓位的出场路径与减仓档无关。
   - 这是本模型的核心假设，局限见第 7 节。
4. **粉尘规则：** 若减仓后剩余 2/3 的名义价值（entry_quantity × c × 2/3）< 5 USDT，则在触发时全平，与线上 `min_position_size` 处理一致。
5. **单次规则：** 每个档位只减一次。候选在 0.8R 减过后，到 1.2R 不再减仓。

每笔交易每臂的净 R（以原始整仓为单位，含全部手续费）：

- 触发：(1/3)·trimR_L + (2/3)·xR；
- 未触发：xR。

其中 trimR、xR 是扣除手续费后的 R。

配对差：Δ_i = R_0.8 − R_1.2。

**撮合必须走 Backtrader（`scripts/backtest`）。** 另写一个纯算术的参考实现，单测要求两者逐笔差 ≤ 1e-9 R。

## 4. 机制校验（在计算 Δ 之前完成；不过则 invalid）

- 用模拟盘交易员各自的档位预测是否触发减仓，与数据库 `tp_trim_done` 标志对比：
  - ec830bb2 用 0.8，其余三个用 1.2；
  - 只取各自最近一次策略更新之后入场的交易：ec830bb2、895dc8b3 为 2026-10-22T01:02:38Z 之后，a2dc5705、a8eb1bdf 为 2026-10-17T07:57:18Z 之后。
- 一致率 ≥ 85% 才有效。报告混淆矩阵。

## 5. 判定（类型 C，K=2，z_K = 2.241）

主统计量：Δ 的均值，按入场 UTC 周（周一开始）聚类，使用 `incremental_filter.weekly_statistics`，z = 均值 / SE。

两半：按入场时间排序，切成笔数相等的前后两半，分别算 Δ 均值。

| 判定 | 条件 |
|---|---|
| invalid | 第 2 节或第 4 节校验未通过，或有效交易 < 100 |
| strong | z ≥ 2.241 且两半 Δ 均 > 0 |
| screen_pass | z ≥ 1 且两半 Δ 均 > 0 |
| fail | 其他情况 |

**后果：**

- **fail：** 向用户建议提前结束线上 `early-trim-0p8r` 配对，需用户同意后才执行。
- **screen_pass / strong：** 配对照预注册继续跑到期满。

## 6. 仅描述，不参与判定

- Δ 按日聚类的 z。
- 按 MFE 分组：<0.8R、[0.8, 1.2)、≥1.2R 三组的笔数和 Δ 均值。
- 触发后、出场前的价格走势：残余仓位相对 0.8R 的走向。
- 敏感性一：按 K 线最高/最低价触及档位就触发，成交价取档位价。
- 敏感性二：滑点 10bp。
- 背景：1.2R 减仓相对完全不减仓的 Δ。
- 按交易员分组的 Δ。

## 7. 局限（预先承认）

- 残余仓位出场外生：LLM 可能因为看到已经减仓而改变后续决策，模型没有反映这一点。
- 样本里有 132 笔来自减仓配对本身，配对的线上结果已经看过。
- 实盘交易 9-29 至 10-22 期间策略配置有过调整。模型只用价格和实际出场价，不依赖当时的减仓档，但残余仓位的出场方式可能受当时配置影响。
- 6 周左右的周聚类数较少，SE 不稳定。
- 不模拟强平、资金费，以及减仓单对市场的冲击。
