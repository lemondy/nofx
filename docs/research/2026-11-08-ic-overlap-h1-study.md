日期：2026-11-08。预注册见 `docs/research/2026-11-08-ic-overlap-h1-prereg.md`（提交 1d053567，sha256 86a20ce0…），审计见 `2026-11-08-ic-overlap-audit.md`。

## 结论

- **主口径没有通过校准。** 主口径是均匀核 HAC（滞后 h）加 Student t 换算。它在 12 组中的误判率都在 2.5%–8.0% 之间，但加密 AR h=1 组的 z 标准差为 1.15002，超出预注册上限 1.15。按规则判为不通过。
- **备选 B 通过。** B 是偏移 0 的不重叠 t，自由度 df = 样本数 − 1，再换算成 z。12 组误判率 2.5%–7.0%，z 标准差 0.873–1.103，全部合格，所以按预注册改用 B。
- **评估器已经换成 B。** 新的 `evaluate.py` sha256 为 `78f70129…3a5454`，算出的 z 与审计脚本里的 B 逐个相同（200×12 组，最大差 0）。
- **干跑影响：**
  - 加密 h=7 的 accepted 从 12 个降到 0 个。
  - 美股 accepted 从 1 个降到 0 个，候选从 11084 个降到 200 个。
  - 加密 h=3 的 accepted 从 2 个降到 1 个：f_eda12cac 的训练 z 是 4.64，门槛 4.65。
  - 加密 h=1 的 accepted 从 4 个降到 3 个：f_a241597b 为 4.57。
- **会改变模拟盘。** 加密因子量化模拟盘的 h=3 入选因子会从 {f_0ce8b2ee, f_eda12cac} 变成只剩 {f_0ce8b2ee}。按预注册第 4 节，部署前需要先告知用户并取得同意。现在还没有合并，也没有部署。

## 2. 实现

`evaluate.overlap_t(series, h)` 的计算步骤：

1. 输入是段内按日期连续的 IC 序列，保留 NaN。
2. 从段内位置 0 开始，每 h 个交易日取一个样本，与 `long_short` 的取样锚点一致；然后去掉 NaN。
3. 边界约定：
   - 有效日少于 20 或样本少于 5，返回 0；
   - 标准差为 0 时饱和到 ±1e12，与 `nw_t` 的约定相同。
4. 计算普通 t，用自由度 k−1 的 Student t 上尾概率换成正态 z。Student t 函数用正则化不完全 Beta 实现，不依赖 scipy。

`segment_metrics` 的 `t` 字段改由它计算，所以 `t_required(K)`、验证门槛 1.65 和前向 verdict 都不用改。

`greedy_ensemble`（`FM_GREEDY_ENSEMBLE`，目前未启用）同步改用新口径。`nw_t` 保留，其他研究脚本还在用。主口径的 HAC 算法留在 `ic_overlap_audit.uniform_hac_t`，作为留档。

新口径下仍为 accepted 的因子（训练 z / 验证 z）：

- h=1：f_e8a4e302 5.59 / 2.50，f_1935a155 5.31 / 4.36，f_ff131b97 4.86 / 4.12；

预注册写下的预期是："加密 h=7 大部分或全部掉出，美股清零；加密 h=1 和 h=3 基本不变"。前两项符合。h=1 和 h=3 各掉了一个贴近门槛的因子，这与预期不完全相符：B 只用每 h 天一个样本，对衰减快的因子会损失检验功效，备选 B 本来就有这个代价。

f_eda12cac 的训练 z 是 4.64，与门槛只差 0.01，而且它的验证 z 3.86 仍然很高，所以这次掉出属于贴线的情况。

还要注意：重分类后，夜间任务只保留每个市场 200 条 rejected，多出的 rejected 会从 zoo 中裁掉，只在 ledger 里计入 K。所以部署之后不能靠回退代码恢复旧的 zoo，只能用部署前的备份恢复。

## 偏离与局限

- 主口径的选择、校准判据和备选 B 都在计算前登记。主口径因标准差超限 0.00002 判为不通过，严格按规则执行。
- 备选 B 只用偏移 0 的样本，所以结果对段起点敏感。在审计里，同一个 h=7 因子在不同偏移下的 t 值相差可达 1–2。这是登记时已经接受的代价，后续如果要改，需要另做登记。
- 4.65 门槛附近的尾部只靠 df 换算，没有做模拟验证。
- 这是评估方法修正，不计入任何交易线的 K。
