# fq_crypto 挖掘器准入修正（算术多空含资金费）的影响评估：预注册（2026-11-07）

- **来源：** `docs/research/2026-11-07-fq-crypto-shortleg-convexity-study.md`。凸性分解显示，秩 IC 看不到凸性；挖掘器准入的主门槛是秩 IC，算术多空只检查符号（`scripts/factor_mining/evaluate.py:135`，`ls_ret > 0`），而且不计资金费。
- **本研究回答两个问题：**
  1. 把准入改为“算术多空净收益（含资金费）显著”之后，快照中的加密因子还剩多少？
  2. 如果剩下的因子能组成新组合 B′，它在前向段是否优于现组合 B？
- **提交时点：** 本文档在计算任何新门槛下的数字之前提交，之后不修改。
- **边界：** 不修改冻结的 `evaluate.py`、挖掘器或每晚任务，不改交易配置。即使通过，也只说明值得另提“挖掘器 v2 准入”方案，由用户决定。

## 1. 数据与基线（冻结）

| 项 | 取值 |
|---|---|
| 快照 | `data/factor_mining/style_neutral/snapshot_20261105/crypto`：zoo.json 共 13,157 个因子，ensemble.json 中 h=3 有 7 个因子。输入哈希与 ML 研究预注册相同，运行时校验 |
| 面板与切分 | `panel.load_panels('crypto', root)`；`panel.make_splits` 按 h 切分，与挖掘器一致 |
| 标签 | `panel.forward_target`：t+1 开盘买入，t+1+h 开盘卖出，算术收益 raw |
| 基线 B | 快照 h=3 ensemble 的 7 个因子，用 `ensemble.ensemble_scores` 合成 |
| K 与 t_req | 每个 horizon 的 K 与 t_req 取快照生成时挖掘器使用的值，从挖掘器的 runs 或 status 记录中读取 |

**S0 复现（必须先通过）：**

- 用原 `evaluate.classify` 和 `Miner._classify_and_correlate` 的逻辑，在快照 zoo 上重分类，13,157 个因子的状态必须与 zoo.json 完全一致。
- 用 `evaluate.long_short` 在快照面板上重算 40 个 accepted 因子的训练段和验证段 `ls_ret`，与 zoo.json 的误差 ≤ 1e-9。
- 任何一项不通过，就先查原因，不进入后续步骤。

## 2. 新准入门槛（冻结）

秩 IC 部分完全不变：训练 t ≥ t_req、训练前后两半同号、训练 IC > 0、验证 IC > 0 且验证 t ≥ 1.65。

只把“训练和验证的 `ls_ret > 0`”替换为下面的门槛。

**每期净收益：** 沿用 `evaluate.long_short` 的调仓日、前后五分位等权和成本口径，再加上资金费：

- 多头腿支付、空头腿收取持有期累计资金费率。累计区间是 t+1 开盘进场日到 t+1+h 出场日（不含出场日）的逐日费率之和，日费率 = 8h 费率 × 3。
- 资金费缺失按 0 处理，并报告覆盖率。
- 净收益 = 多头均值 − 空头均值 − 成本 − mean(多头资金费) + mean(空头资金费)。

**统计量：** ls_t = 均值 / (样本标准差 / √n)。各调仓期互不重叠，不做 HAC。

| 门槛 | 条件 | 角色 |
|---|---|---|
| **A（主）** | 训练 ls_t ≥ 1.65，并且验证 ls_t ≥ 1.65，均为含资金费的净收益 | 决定 B′ |
| A0 | 同 A，但不计资金费 | 只描述，用于区分资金费的作用 |
| S_f | 训练和验证净均值 > 0，计资金费，不看显著性 | 只描述，即“只加资金费、仍只看符号” |

**之后的流程与挖掘器相同：**

- 冗余判定按挖掘器的顺序（按训练 t 降序）和 `CORR_REDUNDANT` = 0.8 重新做。
- 用 `ensemble.select_ensemble_factors(accepted, 3)` 取训练 t 最高的前 20 个，greedy 关闭（与线上一致），得到 B′。

## 3. S1 判定（仅当 B′ 非空且与 B 不同时进行）

- **主检验区间：** 只用前向段 2026-05-04 → 快照末日。
  - 原因：新门槛在选因子时用到了验证段，验证段对 B′ 和 B 都是样本内。
  - 验证段的配对结果只作描述。
- **回测：** 两组都用 `ensemble_forward_study.backtest(panels, score, start, end, 3)`。
- **统计量：** 配对差 Δ = B′ 日收益 − B 日收益；按周聚类 SE，用 `style_neutral_study.weekly_statistics`；z = 均值 / SE。
- **记账：** track 为 fq_crypto，K = 7（运行时从账本核对：fq_crypto 已有 6 个计数的 S1）。z_K = Φ⁻¹(1 − 0.05/14) ≈ 2.69。idea_id 为 `fq-crypto-admission-arith-v1`，baseline 为当前 h=3 ensemble。
- **判定**（按顺序取第一个满足的）：
  1. invalid：前向配对日少于 120 天，或 B′ 有非有限分数；
  2. strong：z ≥ z_K；
  3. screen_pass：z ≥ 1，且前向段前后两半的 Δ 均值都 > 0；
  4. fail：其他情况。
- **特殊情况：**
  - B′ 为空：判为 `no_factors`，不计 K、不写账本。其含义是：按新门槛，快照里没有可交易的 h=3 加密因子。
  - B′ 与 B 完全相同：判为 `unchanged`，同样不计 K。

## 4. 描述性输出

1. **各 horizon（1、3、7）在四套门槛下的数量：** 原规则、S_f、A0、A 各自的 accepted、candidate、redundant 数；以及 IC 部分通过、但被新门槛拒掉的数量。
2. **线上 7 个因子的明细：** 训练和验证的 ls_ret、含资金费的净均值，ls_t（不计和计资金费），以及在 A、A0、S_f 下是否通过。
3. **B′ 的组成**（若非空）：因子 id、表达式、族、训练 t、ls_t；以及与 B 的分数相关、对 vol_30 的截面相关（复用 ML 研究的风格特征定义）。
4. **B 与 B′ 的分段回测：** 训练段只给单位腿描述；验证段和前向段给净收益、夏普、最大回撤、资金费、换手。
5. **资金费覆盖率：** 按分段报告。

## 5. 已知偏差与局限

- **数据已看过：** 前向段已被多项研究看过，S1 只作筛选。
- **统计效力有限：** 前向段约 180 天，效力有限。
- **只用快照因子：** 新门槛只作用于快照中已有的因子，没有重新挖掘。真实的挖掘器 v2 会搜到不同的表达式，本研究只估计“同一批候选在新门槛下的去留”。
- **幸存者偏差：** 币池是快照当时的成员（`crypto-universe-expansion`）。
- **双重使用验证段：** 新门槛同时用验证段选因子；主检验因此只用前向段。
