# C1 限价带宽入场：S2 线上验证方案（2026-11-13，草案）

本文是方案，**不是最终预注册**。最终预注册要等代码完成、配对开始之前另行提交。本文提交时没有改代码、配置和数据库。

## 0. 结论先行

- **框架默认的 S2 不可行。** 按增量评估框架的默认做法，应建两个模拟盘，比较各自的 avgR。但 S1 测到的效应约为 +0.02R/笔，而两个 LLM 模拟盘各自做出不同决策，每笔 σ ≈ 1R。30 天配对的 SE 约 0.025R（框架文档已有估算），大于效应本身，测不出来。
- **所以 S2 改为“同笔交易内配对”。** 只让候选模拟盘真实执行限价带宽入场；每笔交易的“如果当时市价入场”的结果，用下单时记录的参考价反算。出场相同，所以差值只来自入场，σ_Δ 约 0.09R（S1 实测）。30 天约 100–200 笔，SE 约 0.006–0.009R，足以分辨 0.02R。
- **S2 要验证的是 S1 无法验证的三件事：**
  1. 真实代码路径：挂单、超时转市价、各种撤单和闸门；
  2. 挂单期间 LLM 的行为：此时看到的是挂单而不是持仓，会不会重复下单或改变后续决策；
  3. 新样本：2026-11 下旬之后的行情，多头是否仍然约为零。
- **S2 测不了真实排队。** 模拟盘的限价单在后续 1m K 线**触价即成交**，没有队列（`trader/paper/paper.go` 第 6–7 行）。这一点只能靠下文 2.5 的保守成交选项来近似，或者将来用实盘小额验证。
- **需要写代码。** 涉及下单执行路径，按用户分工至少交给 Codex，主 agent 审查。部署要重建并重启后端，需要用户批准。

## 1. 为什么不能直接打开 `limit_entry_enabled`

现行限价入场是一整套“锚点限价”机制，不只是执行方式：

- 提示词会变：`kernel/engine_prompt.go` 第 205–438 行按 `LimitEntryEnabled` 改写入场说明和信号图例，LLM 会改为输出 `open_long_limit` 并自己给出价位。
- 信号层闸门会变：`kernel/signal_layer.go` 第 1942 行起，锚点会控制限价路径；`marketExceptionGate`（`trader/auto_trader_orders.go` 第 147 行起）会把没有“市价例外证据”的市价单降级为锚点限价。
- 挂单深度不同：锚点按 ATR 计算，深度为 0.15–1.2%，比 θ\* 深 2–15 倍。S1 显示挂单越深越差，30bp 时 z 已降到 1.30。
- 超时只撤单：`processPendingEntries` 到期后取消挂单，不转市价（`trader/auto_trader_pending.go` 第 789 行）；只有价格已越过锚点时才转市价。

所以打开这个开关，同时改动了提示词、闸门和执行三处，不是 S1 测过的改动。

## 2. 代码改动（新增执行层选项，提示词不变）

### 2.1 配置

在 `store.RiskControlConfig` 新增字段（JSON 名待定），全部默认关闭：

| 字段 | 含义 | S2 取值 |
|---|---|---|
| `entry_band_enabled` | 对 LLM 的市价开仓指令改用带宽限价执行 | 候选 true，对照 false |
| `entry_band_mode` | `roll`：θ\* 按 S1 公式由 24h 1m Roll 估计计算；`fixed`：固定深度 | `roll` |
| `entry_band_phi_bps` | φ | 8 |
| `entry_band_fixed_bps` | fixed 模式的深度 | 不用 |
| `entry_band_timeout_min` | 超时转市价的时限 | 30 |

- 只在 `limit_entry_enabled=false`（市价策略）时生效。与 `limit_entry_enabled=true` 同时打开时，配置校验报错。
- **提示词不能读这些字段。** 加一个测试：开关打开与关闭时，同一输入构建出的系统提示词和用户提示词逐字节相同。

### 2.2 下单

LLM 输出 `open_long`/`open_short` 后，照常走全部现有闸门和仓位计算（与市价完全一样），只在最后一步改变执行：

1. 记录参考价 P_ref，即下单时刻的实时价格。
2. 计算 θ\*：取最近 1440 根已收盘的 1m K 线，按 S1 的 Roll 估计算出 s_G，再按带宽方程算 θ\*。数据不足时取 θ\* = φ，并记录原因。
3. 按 P_ref·(1 ∓ θ\*) 挂限价单。数量、止损、止盈与市价路径算出的完全相同（S1 也是同数量）。
4. 登记为 pendingEntry，带上：模式 `band`、P_ref、θ\*、s_G、截止时间（挂单时间 + 30 分钟）。

### 2.3 挂单生命周期（`processPendingEntries`）

| 事件 | 处理 |
|---|---|
| 成交 | 沿用现有成交后的保护单流程 |
| 到期未成交 | 撤单；撤单成功后，按市价开仓，并在当时价格上重新校验现有风控（沿用越过锚点时转市价的那条路径）。价格已越过止损时放弃，记为 `invalidated` |
| 部分成交后到期 | 剩余部分转市价，已成交部分保持保护 |
| 价格越过止损 | 撤单，记为 `invalidated`（与现有逻辑相同） |
| 账户熔断、币种排除 | 撤单（安全否决保留） |
| 方向复查（`directionRecheck`） | **band 挂单不做方向复查**。S1 保留了所有交易；方向复查会让候选比对照少做交易，混入“做得更少”的效应。需要用户确认，见第 6 节 |
| 挂单期间 LLM 对同一币同一方向再次开仓 | 视为重复，忽略并计数 |
| 挂单期间 LLM 要求平仓 | 撤单，记为 `ai_cancelled` 并计数 |

### 2.4 记录

每笔 band 入场写一条结构化记录（新表或 decision action 的扩展字段），包括：P_ref、θ\*、s_G、限价、挂单时间、结果（filled / fallback / invalidated / ai_cancelled）、成交价、成交时间、手续费。S2 报告完全依赖这条记录。

### 2.5 模拟盘的保守成交选项

- `paper.Config` 新增 `LimitTradeThroughBps`，默认 0，即保持现行的触价成交。大于 0 时，买入限价单要求 1m 最低价 ≤ L·(1 − x)，卖出单对称。
- S2 的候选模拟盘设为 **x = 2bp**。S1 事后检查显示，2bp 时 Δ +0.017，z 4.4；5bp 时 Δ 降到 +0.005。2bp 是兼顾现实与保守的折中，最终取值在预注册里固定。
- 同时记录每笔挂单期间的 1m 极值，这样 S2 报告可以同时给出触价成交和穿价 2bp、5bp 三种口径下的成交率。

### 2.6 测试

需要覆盖以下情形：

- θ\* 计算，结果应与 `scripts/backtest/limit_band_entry_study.py` 一致，用同一组合成数据逐笔比较；
- 挂单、成交、到期转市价、部分成交；
- 价格越过止损、熔断撤单；
- 重复开仓忽略、LLM 平仓撤单；

## 4. 判定（最终在预注册中冻结）

**主统计量：同笔交易内的配对差。** 对候选模拟盘的每笔已平仓交易：

- 候选净 R：用实际入场价和手续费计算。
- 反事实市价净 R：入场价取 P_ref·(1 + s·3bp)，吃单费 5bp，出场与候选相同。
  - 结果为 invalidated 或 ai_cancelled、因而没有持仓的，候选记 0；市价臂则按 S1 的方法，用 1m K 线从 P_ref 推到该笔决策的止损、止盈或 LLM 实际平仓时刻。这一部分要在预注册中写清楚，或者单列不计入主统计。
- Δ = 候选 − 反事实，按 UTC 周聚类。另报告按日聚类的结果。

**辅助：对照模拟盘上的 S1 前向复现。** 对照臂的市价交易，用冻结的 S1 脚本（新时间窗，另行登记）计算反事实 Δ。两边方向一致才算稳健。

| 结论 | 条件（草案） |
|---|---|
| harm_stop | 运行 ≥ 14 天且 Δ < −2·SE，或真实代码出现重复持仓、未保护持仓等执行错误 |
| promote（进入实盘讨论） | ≥ 30 天且候选 ≥ 100 笔；Δ 的单侧 95% 下界 > 0；两半 Δ 均 > 0；missed、invalidated、ai_cancelled 合计 ≤ 10%；穿价 2bp 口径下成交率 ≥ 70% |
| short_only | 满足 promote，但多头 Δ 的 z ≤ −2：只建议对空头启用 |
| extend | 达到最短运行但 SE > 0.01：延长 2 周，最多一次 |
| reject | 其余 |

**两臂整体 avgR 差只报告，不参与判定。** 原因见第 0 节，功效不足。

**K。** S2 不增加 K（K 只计 S1），但要在账本写一行 S2 事件。
