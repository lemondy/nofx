# Kronos 与 KiT（K 线基础模型）评估（2026-11-10）

**结论档位：证据不足。** 两个模型都不能直接接入 nofx。美股和加密、LLM 交易员和 factor_quant 四种组合都不能。

- **Kronos**（清华，AAAI 2026）的推理代码和权重是干净的：MIT 许可，safetensors 格式，预训练数据截止 2024-06。但论文的收益信号主要来自 A 股，加密的 RankIC 只有 0.033，而且与简单线性模型（DLinear）差距不大。
- **KiT**（UCLA/东南大学，2026-09）宣称的回测收益不可信：
  - 论文回测的 12 个月中，有 8 个月落在验证期（按论文口径）或训练期（按发布权重口径）；
  - 训练截止日在三处说法互相矛盾；
  - 美股的 RankIC 约为 0，加密只覆盖 28 个币；
  - 训练代码未发布，权重是需要 `weights_only=False` 才能加载的 pickle。
- 只有一个值得低成本检验的方向：用 Kronos 零样本生成的多条路径，在 LLM 开仓时估计“走势不利的概率”，作为开仓否决（H1，B 类）。先验偏低。预注册已写好（`docs/research/2026-11-11-kronos-entry-veto-s1-prereg.md`）。**2026-11-11 经用户同意已运行：S1 判 fewer_trades（剔除 66.5%，z −2.66，方向相反），不接入**，见 `docs/research/2026-11-11-kronos-entry-veto-s1-study.md`。
- 本轮只在合成数据上跑了 Kronos-small 推理冒烟测试，不碰真实价格，不计 K（第 6 节）。
  - 模型可用且可复现，CPU 上每次预测约 30 秒；
  - 但在无漂移随机游走上，它给出过度自信的均值回归预测：82% 的序列 16 条路径几乎同向，偏移与窗口 z 分数相关 −0.78，12% 的 K 线不合法。所以它的读数近似一个“区间位置反转”特征。

## 2. 核心机制

| | Kronos | KiT |
|---|---|---|
| 表示 | 每根 K 线的 OHLCVA 先按窗口做 z-score（裁剪到 ±5），再由 BSQ 分层量化成粗、细两个子 token | 五维对数比 (r_gap, r_body, r_up, r_dn, v)，见 `kit_v1/data/features.py`。不需要分词器，按（市场、周期、特征）做 MAD 缩放加 tanh 软裁剪 |
| 生成 | 仅解码器 Transformer，自回归逐根采样（温度 T、top-p） | 扩散 Transformer（DiT）+ flow matching。历史不加噪，整段预测窗一次生成；Euler 32 步，K=16 条路径 |
| 条件 | 时间戳特征（分、时、星期、日、月） | 市场、板块、**单个标的 ID**（4096 词表）、周期用 AdaLN 注入；时钟、交易时段、日历、事件按根加到 token 上 |
| 规模 | mini 4.1M / small 24.7M / base 102M（large 499M 未开源）；上下文 512 | S 31M / M 101M / L 284M；上下文按周期固定，例如 5m 为 960 根历史、96 根预测 |
| 预训练数据 | 45 个交易所、120 亿根 K 线，截止 2024-06 | A 股 3914 只、美股 888 只、加密 28 个，2016-08 至 2026-04-10，共 30 亿根 |

**两者共同的读出口径：**
- 收益预测取多条采样路径终点收益的均值；
- 评价指标是**截面** RankIC，即同一时点各标的之间的排序相关；
- 交易验证都是 A 股 top-N 多头组合。

**Kronos 信号的一个细节：** 在 `finetune/qlib_test.py` 中，信号是“归一化空间里的预测收盘价减去最后收盘价”，也就是以窗口内价格标准差为单位的预测偏离。最后收盘价相对窗口均值越高，模型越倾向预测回归。这个信号天然和“价格在区间中的位置”以及短期反转相关，而 A 股的短期反转本来就是很强的因子。

**主要问题：**

1. **回测样本内。** 论文回测 2025.05–2026.04，其中 2025.05–2025.12 共 8 个月属于验证期，而验证期用于早停，也用于选 Top-N 和调仓频率。按发布权重的说明，这 8 个月甚至在训练期内。真正样本外的只有 2026-01 至 04-10 约 3.3 个月。
2. **训练截止日有三种说法：**
   - 论文写训练截止 2023-12-31；
   - GitHub README 的权重表写 `step_market_284M.pt` 训练区间为 2016-01-01 至 2025-12-31，第二个权重到 2026-04-10，覆盖整个测试窗；
   - 仓库 `configs/dit_300m.yaml` 写 `train_end: 2023-12-31`、`val_end: 2024-06-30`、`test_start: 2024-07-01`。

   训练代码未发布，无法核实。`eval/infer_for_eval.py` 默认用第一个权重，并把权重自带的 `train_end` 写进 meta，但没有检查它是否早于评估窗。
3. **幸存者偏差。**
   - 论文写所有标的“均从 2016-08-01 至 2026-04-10”，看起来是当前仍在交易的标的，没有提到退市；
   - 加密只有 28 个“产品”；
   - 演示的 100 只 A 股没有说明挑选方法（`instruments.json` 只有代码、板块 0 和词表编号）。其 3 个月等权均值约 +2%，中位数在 5m 口径下为 −14%，分布严重右偏。在这样的池子里，top10 赌高波动很容易出现大赢家。
4. **统计力不足。**
   - 测试窗 3.3 个月，日线只有 3–5 个锚点；
   - 论文和仓库都没给 RankIC 的标准误或 t 值；
   - 7 个周期 × 3 个市场的结果没有做多重检验校正。
5. **基线偏弱且不对称。**
   - 没有短期反转、动量、滞后波动率这类简单因子基线；
   - GARCH 没有拟合；
   - Kronos-base-FT 是“按测试集最好成绩挑选的权重”（附录 A.2）。这对基线有利，但也说明作者在测试集上做过选择。
6. **权重加载有安全风险。** `kit_v1/infer/loader.py` 用 `torch.load(..., weights_only=False)` 加载 1.14 GB 的 pickle，等于执行权重文件里的任意代码。账号 `Lucifer744` 没有组织背书。本轮因此没有下载 KiT 权重。
7. **执行口径偏乐观。** 演示回测用锚点那根 K 线收盘计算的信号，又在同一个收盘价买入。A 股的涨跌停和 T+1 有建模；印花税在论文里写 10bp，代码里是 5bp。

**正面的地方：** 推理端代码是因果的。
- `features.py` 的成交量 EMA 严格只用 t−1 之前的数据；
- `normalize.fit_stats` 只用 `train_end` 之前的数据；
- `prepare_inference_window` 按 `end_ts` 截断历史；
- 未来的时间戳由交易日历生成。

没有发现推理阶段的前视。

**相关的已结束研究：**
- ML 多特征 S1（ridge/RFF，两个市场都失败，PR #96）：不再提议在现有数据上做 ML 打分。基础模型带来的是“外部预训练语料”这一新信息源，形式上不算重复，但同一条教训适用：截面 RankIC 不等于 P&L。
- 因子否决 LLM 做多（crypto_llm，2026-11-04）：fewer_trades，方向相反。这是与 H1 最接近的前例。
- 美股因子挖掘基本为空，只有动量（2026-11-05/06），所以美股不提假设。
- 订单流/VWAP 对提示词指标无增量（PR #59）；Fib+FVG+BOS 入场无优势（PR #62）。

## 5. 可检验的假设（按优先级）

### H1（优先，已预注册，未运行）：Kronos 路径的“不利概率”作 LLM 开仓否决

- **机制：** 如果 Kronos 从 5m K 线里学到了 LLM 提示词指标之外的短期路径信息，那么当模型生成的大多数路径在持仓跨度内都朝不利方向走时，这笔开仓的期望 R 应该低于平均。
- **改动：** B 类开仓过滤，track 为 `crypto_llm`，K=5。
  - 开仓前取 512 根已收盘的 5m K 线，Kronos-small 零样本生成 16 条 60 根（5 小时）的路径；
  - p_adverse = 终点收盘价位于不利一侧的路径占比；p_adverse ≥ 0.75 则否决。
- **数据：** 冻结的 439 笔 LLM 交易（`data/llm_trim_offline/export_v1/trades.jsonl`）。每笔的 R 取早减仓研究里 Backtrader 计算的 `no_trim.r`。另需下载入场前的 5m K 线。
- **指标：** `incremental_filter` 的 ΔavgR（保留组对全体）、随机剔除安慰剂 z 与分位、前后两半都 > 0。决策指标优先；预测命中率只作描述。
- **失败条件：** 框架判 fail、fewer_trades 或 invalid。另外，剔除少于 20 笔判 invalid（没有统计力）。
- **成本：** 下载 439 次 K 线；本机 CPU 推理约 3.7 小时（第 6 节）；脚本约 400 行，复用 `incremental_filter`。
- **冲突：** 与“LLM 入场无优势”的现状一致，否决只会减少交易；若通过，接入需要 Python 侧车服务。
- **先验：** 低。依据：
  - 论文自己的加密截面 RankIC 只有 0.03–0.05；
  - 同类的因子否决已经失败；
  - 439 笔、剔除 30% 时，ΔavgR 的安慰剂标准误约 0.03–0.04R；
  - 合成数据诊断显示，模型读数主要是“向窗口均值回归”，可以用零成本代理复现（第 6 节）。预注册因此要求 Kronos 超过同剔除笔数的代理否决，才能进入 S2。

### H2（备选，未预注册）：Kronos 日线预测作 fq_crypto 排序分

- **改动：** A 类，换信号层，组合构建与 Backtrader 执行不变。
- **为什么暂不做：**
  - ML 多特征失败的机制（只学到低波动、空头腿亏损）对任何截面排序模型都成立；
  - 算力大：685 个币 × 每周一个锚点 × 约 200 周，约 13 万次预测；
  - 只有 H1 显示 Kronos 有非平凡信息时才值得做。

### H3（备选，未预注册）：路径分布作止损或仓位的风险层

- **改动：** 用 Kronos/KiT 生成路径的不利偏移分位，与当前的 ATR 锚定止损距离、HAR 缩放比较。
- **为什么暂不做：** DVOL 研究已经表明，预测更准也可能在仓位决策上更差。论文的波动率基线又没有 HAR 或滞后 RV，增量无从判断。可以先做描述性检查，不计 K。

**美股：** 不提假设。KiT 的美股 RankIC 约为 0，部分周期为负；fq_us 现有的唯一信号是动量。

**知识笔记（不改交易）：**
- KiT 的五维对数比 K 线编码与价格水平无关、可逆，在需要压缩 K 线输入时可以参考。
- 两篇论文都只报告截面 RankIC 的均值。nofx 的评估要求报告锚点数和标准误，并以决策指标为准，这个做法应保持。

## 6. 可用性冒烟测试（合成数据，不计 K）

脚本在草稿区，不入仓库：`kronos_smoke.py`。
- 模型：Kronos-small，从固定的 HF 版本加载 safetensors；
- 数据：6 条无漂移 GBM 合成序列，每条 512 根 5m K 线；
- 预测：60 根 × 16 条路径，同时保留每条路径，不取平均。

**可用性（6 条序列）：**

| 项 | CPU | MPS（Apple Silicon） |
|---|---|---|
| 每次预测耗时（512 根上下文，60 根 × 16 条路径） | 29.5–31.9 秒 | 15.4–17.4 秒 |
| 同种子重跑的最大差值 | 0 | 0 |
| 输出形状 | [16, 60, 6] | [16, 60, 6] |

- 权重 sha256：small 为 `b082dfcb…`，tokenizer 为 `59d85f6a…`，与 HF 的 LFS 校验值一致。
- 同种子下 CPU 与 MPS 的结果不同，所以正式运行固定用 CPU。
- 按 CPU 速度，439 笔约需 3.7 小时。

**合成数据诊断（50 条无漂移 GBM，MPS，脚本 `kronos_synth_diag.py`）：**

| 指标 | 值 | 随机游走上应有的值 |
|---|---|---|
| p_up 均值 | 0.531 | ≈ 0.5 |
| p_up ≤ 0.125 或 ≥ 0.875 的序列占比 | 82% | 很小（真实的 p_up 应接近 0.5） |
| 预测 5 小时均值偏移 / (σ·√60) 的中位绝对值 | 2.47 | ≈ 0（只有采样误差） |
| 路径终点离散度 / (σ·√60) 的中位数 | 0.60 | ≈ 1 |
| 偏移与最后收盘价窗口 z 分数的相关 | −0.78 | ≈ 0 |
| 偏移与过去 60 根收益的相关 | −0.18 | ≈ 0 |
| 不合法 K 线占比（high < max(O,C) 或 low > min(O,C)） | 12% | 0 |

**解读：**
- 整体上没有方向偏差（均值 0.53），但每条序列上，Kronos-small 都给出过度自信的均值回归判断：最后价格在窗口高位就预测下跌，在低位就预测上涨，而且 16 条路径几乎一致；
- 生成路径的离散度明显低于真实波动，所以“路径不利概率”不是校准过的概率，近似一个“区间位置反转”的方向判断；
- KiT 论文批评 Kronos 会生成不合法 K 线，这一点在本测试中属实。

**对 H1 的影响：**
- H1 实际检验的很大一部分是“价格在 42 小时窗口中的位置”，这个特征不需要 Kronos 就能算；
- 预注册因此加入零成本代理对照（同剔除笔数的窗口 z 分数否决），并规定 Kronos 必须超过代理才进入 S2；
- 先验进一步下调。以上都只用了合成数据，在预注册提交前完成，不计 K。
