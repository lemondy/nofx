# AI 决策 prompt 程序化增强(对应复盘 14 点)

## 总原则
把「AI 自己算/自己判断」的部分下沉为程序预计算字段,AI 只做排序、解释和选择。所有改动均为 **prompt 侧数据/语义增强,不改任何执行端硬门逻辑**(执行端 validateOpenRisk / applyHardRiskGates 原样保留,继续兜底)。

## 1. 新增 `rr_scan` + `hard_entry_gate`(点 1/2/4/5/7/8/10)
文件:`kernel/signal_layer.go`(`ComputeSymbolSignals` 内,在 anchors/min_size/data_quality/execution_filter 都算完之后)

每个方向(long/short)输出:
```json
"hard_entry_gate": {
  "long": {
    "allowed": false,
    "entry_price": 0.020501,          // 限价锚点可用=锚点价;被抑制=现价(市场单口径)
    "limit_allowed": true,            // 锚点未被抑制(与方向禁止彻底拆开,点7)
    "stop_floor_pct": 6.89,           // = 噪声下限(最佳情况止损)
    "rr_scan": {
      "targets_scanned": 5,           // 全部 TF 的 S/R 数组并集去重后的目标数
      "best_target": 0.02139, "best_rr": 0.64,
      "first_rr_ge_target": null,     // 从近到远第一个 RR≥min_rr 的结构位(AI 应选的 TP)
      "usable": false
    },
    "failed": ["RR_MAX_0.64", ...]    // 程序判定的阻断码列表
  },
  "short": { "failed": ["MICRO_TREND_NOT_SHORT", "LIMIT_ANCHOR_SUPPRESSED", ...] }
}
```
- RR 用 **floor 止损距离**(止损最窄=RR 上限)计算:`best_rr < min_rr` ⇒ 该币该方向结构性不可能过 RR 门,`RR_MAX_x.xx` 成为确定性结论——正是 SAGA/DELL/CHIP 案例要的措辞。
- 目标集:复用现有各 TF `resistance/support` 数组并集,近→远排序,`inList` 0.05% 去重。
- `failed` 词表(程序可判定部分):`MICRO_TREND_NOT_{LONG,SHORT}`、`LIMIT_ANCHOR_SUPPRESSED`、`RR_MAX_x.xx`、`DATA_INSUFFICIENT`、`MIN_SIZE_DEAD_ZONE`、`LOSS_STREAK_BANNED`、`STOCK_WEEKEND`。
- `allowed = 全部阻断为空`。AI 不再需要自己拼「三道门」。

## 2. `bias` 语义分层(点 3)
同文件新增顶层小块:
```json
"bias": { "scanner": "short", "structure": "long", "execution": "long_only", "directional_score": 33 }
```
structure 由 directional_score 符号推导(±20 内=mixed),execution 由 execution_filter 推导。字典文案明确:scanner short ≠ 市场证据偏空。

## 3. `funding_rollover` 程序化(点 6)
- `market/data.go`:新增 funding 结算历史拉取(复用 `/fapi/v1/fundingRate?limit=6` 端点与 `binanceGetJSON`),5min TTL 缓存(与现有 FundingRateCache 同模式),存入 `Data.FundingHistoryRates`。
- `kernel/signal_layer.go` derivatives 块输出:
```json
"funding_rollover": { "detected": true, "from_annualized_pct": 32.4, "to_annualized_pct": 10.9, "settles_back": 3, "definition": "..." }
```
判定逻辑与 shortscan `AnalyzeShort` L269-270 对齐(前高 > 每期阈值 且当前值已回落),阈值从策略配置 `ShortScanFundingRatePct` 换算——两处用同一个纯函数,避免口径漂移。
- 策略 prompt 做空资金费率条件② 改为「以 `derivatives.funding_rollover.detected` 为准,禁止从 scanner patterns『资金费率回落』推断」(点 6 逻辑缺口闭合)。

## 4. 交易状态机 + wait 语义(点 11/12/13)
- `kernel/engine.go`:Decision 新增可选字段 `wait_state`(枚举 `BLOCKED/WATCH_LONG/WATCH_SHORT/READY_LONG/READY_SHORT`,复用 ValidDecisionStages 模式做校验+归一化)+ `next_trigger`(自由文本必填当 wait_state=WATCH_*)。落 `entry_assessments` 新列(store/entry_assessment.go)。
- `DeriveWaitStage` 兼容:wait 决策带 wait_state 时优先用它映射 stage。
- prompt 输出 schema 渲染 + 规则:wait 必须给 wait_state + next_trigger;next_trigger 格式统一为 `事件 + RECHECK_ALL_HARD_GATES`(点 12「等15m转down」修正);新增时间语义规则:「决策在下一个周期快照重评,禁止输出任何以周/日为单位的搁置结论」(点 13)。

## 5. 数据新鲜度优先级 + 榜单边界(点 14)
`engine_prompt.go` BuildUserPrompt 顶部与三个榜单的「边界」免责声明统一加:
```
数据时间优先级: Structured Signal timestamp > 实时 derivatives > rankings/scanner 快照。
同字段冲突取新值;榜单价格严禁参与 entry/SL/TP/RR 精确计算,只作 market context。
```

## 6. 文案对齐(点 1/2 的规则侧)
- TP 选位规则 bullet:改为「程序已在 `rr_scan.first_rr_ge_target` 给出应选目标,直接采用;`rr_scan.usable=false` 时该方向 RR 门必失败,直接 wait」。
- `renderSignalBlock` 字段字典行追加 `rr_scan / hard_entry_gate / bias / funding_rollover` 说明。
- 执行端 RR 双锚校验不动(仍对 AI 输出的 TP 复核)。

## 7. 测试

## 8. 部署
按既有流程:commit(每个逻辑块一次)→ rebuild → kill 旧 PID → nohup 重启(不分一条 && 链)→ 观察下一周期 prompt 里新字段实际渲染 + config 漂移自检无告警。

## 明确不做
- 不改任何执行端拒单逻辑/阈值;不加「TP 必须等于 first_rr_ge_target」的新执行端硬门(程序字段给出后先观察 AI 采纳率,再决定是否升级为硬门)。
- 不删除 scanner_hint(仍为辅助证据,只是 bias 分层让语义更清楚)。
